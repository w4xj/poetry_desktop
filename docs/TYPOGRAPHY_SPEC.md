- **文档状态**：产品排版规范，待程序员评审
- **版本**：1.0
- **日期**：2026-08-05
- **适用范围**：诗词壁纸合成、预览、显示设置界面和相关验收
- **本轮限制**：仅新增产品设计文档，不修改业务代码
- **关联文档**：`docs/PRODUCT_SPEC.md`、`docs/UI_REDESIGN.md`
- **关联代码**：`src/core/renderer.cpp`、`src/core/models.h`、`src/core/models.cpp`

## 1. 背景与问题结论

用户反馈：当前壁纸中的诗词名、诗人、朝代、正文使用同一字体和字号，观看效果差。

经审查现有实现，问题是确定存在的：

1. `Poem` 已经分别保存 `title`、`author`、`dynasty`、`content` 四个字段，但渲染器没有按字段分别排版。
2. `renderer.cpp` 当前将标题、作者/朝代和正文拼接为一个 `QString`，使用换行连接：

   ```text
   标题
   作者 · 朝代
   正文
   ```

3. 当前渲染只创建一个 `QFont`，并统一使用：
   - `RenderSettings::fontFamily`
   - `RenderSettings::fontPointSize`
   - `RenderSettings::textColor`
4. 当前文本使用一次 `QPainter::drawText()` 绘制，无法分别控制标题、落款和正文的字重、字号、颜色、行距和间距。
5. 当前超长判断针对整段拼接文本，不能分别保护标题、落款和正文的视觉层级。

因此本规范要求将渲染对象从“一个文本块”升级为“三类文本块”：

```text
标题块       TitleBlock
落款块       BylineBlock：作者、朝代
正文块       BodyBlock
```

`Poem` 数据结构已经能够支持这三类内容，第一版不需要改变诗词 JSON 的基本字段；需要新增的是排版配置和分块渲染策略。

## 2. 排版目标与设计原则

### 2.1 目标

在不增加复杂编辑器的前提下，使用户在以下常见场景中都能快速读清楚诗词：

- 1920×1080 横屏壁纸；
- 2560×1440 横屏壁纸；
- 图片亮暗不均、细节较多的背景；
- 标题、作者、朝代均存在；
- 只有标题或只有作者；
- 正文包含多行和中文标点；
- 正文较长但仍可作为壁纸阅读。

### 2.2 原则

1. **层级优先**：标题最突出，正文最易连续阅读，作者/朝代作为辅助信息。
2. **同一字体家族、不同字阶**：默认使用同一中文字体家族，分别调整字号和字重；高级设置允许独立指定字体。
3. **不依赖颜色表达全部层级**：即使图片复杂或颜色接近，也必须通过字号、字重、间距和底板保持区分。
4. **不静默裁剪**：任何文字被截断，都必须按照明确的溢出策略处理并向用户反馈。
5. **缺字段自动收缩**：标题、作者或朝代为空时不显示空行，不留下不自然的大间隔。
6. **预览与最终壁纸一致**：预览和实际输出必须共用同一个排版配置及渲染路径。
7. **默认简单，进阶可调**：常用设置首屏可理解，高级排版选项折叠展示，避免继续造成界面杂乱。
8. **按画布缩放**：字号、间距和安全边距以目标画布短边或基准宽度进行比例缩放，不能只依赖固定逻辑像素。

## 3. 默认排版模板

### 3.1 默认模板名称

默认模板名称：**“雅致左下”**。

默认布局：

```text
┌──────────────────────────────┐
│                              │
│          图片主体            │
│                              │
│  标题                        │
│  作者 · 朝代                │
│                              │
│  正文第一行                  │
│  正文第二行                  │
│  正文第三行                  │
└──────────────────────────────┘
```

默认选择左下锚点、左对齐，原因是：

- 中文正文连续阅读时左对齐更稳定；
- 左下区域通常适合放置完整文字块；
- 避免默认右下文字被桌面图标或系统元素遮挡；
- 与现有 `Anchor::BottomLeft` 能够兼容。

若用户选择“居中”锚点，默认切换为居中对齐；用户可以在设置中手动覆盖对齐方式。

### 3.2 文本块顺序

固定顺序如下：

1. 标题块：有标题时显示；
2. 落款块：作者和朝代至少有一个时显示；
3. 标题与落款之间的分隔间距；
4. 正文块：正文是必需项。

标题、落款和正文不能再通过一个带换行符的字符串统一绘制，必须分别测量和绘制。

## 4. 字号、字重和颜色规范

### 4.1 基准尺寸

以下数值以 **1920×1080 输出画布**为基准，单位为输出像素。其他分辨率按照缩放因子计算：

```text
scale = min(canvasWidth / 1920, canvasHeight / 1080)
```

对于特别小的画布，仍需设置合理下限；不能因为缩放因子过小导致文字不可读。

### 4.2 默认字号比例

正文作为基准字号 `B`。

| 文本块 | 默认字号 | 相对正文比例 | 视觉用途 |
|---|---:|---:|---|
| 标题 | `1.50B` | 150% | 建立主题和第一视觉焦点 |
| 作者 | `0.72B` | 72% | 辅助说明 |
| 朝代 | `0.68B` | 68% | 辅助说明，弱于作者 |
| 正文 | `B` | 100% | 主要阅读内容 |

默认像素值如下：

| 文本块 | 默认值 | 允许范围 |
|---|---:|---:|
| 正文 | 32 px | 20～64 px |
| 标题 | 48 px | 28～96 px |
| 作者 | 23 px | 16～48 px |
| 朝代 | 22 px | 16～48 px |

实现时不要求直接使用像素字号；如果 Qt 使用 point size，应根据目标输出 DPI 和当前渲染比例转换，但验收应以最终输出图片中的相对视觉效果为准。

默认标题字号不得小于正文的 1.3 倍；默认作者/朝代字号不得大于正文的 0.85 倍。

### 4.3 字重

默认使用以下字重：

| 文本块 | 默认字重 | Qt 建议 |
|---|---|---|
| 标题 | 半粗 | `QFont::DemiBold`，必要时回退到 `Bold` |
| 作者 | 中等 | `QFont::Medium`，不可用时回退到 `Normal` |
| 朝代 | 常规 | `QFont::Normal` |
| 正文 | 常规 | `QFont::Normal` |

规则：

- 标题不使用极粗黑体作为默认值，避免破坏古典诗词气质；
- 正文不使用粗体，避免多行阅读疲劳；
- 作者可以略高于朝代，但不能比标题更醒目；
- 字体家族没有对应字重时，必须使用最接近的可用字重，不得显示空白或乱码。

### 4.4 默认颜色

默认使用白色系，但通过透明度区分层级：

| 文本块 | 默认颜色 | Alpha | 说明 |
|---|---|---:|---|
| 标题 | `#FFFFFFFF` | 100% | 最高对比度 |
| 作者 | `#EBFFFFFF` | 92% | 清晰但弱于标题 |
| 朝代 | `#B8FFFFFF` | 72% | 降低辅助信息权重 |
| 正文 | `#F5FFFFFF` | 96% | 保证长文本阅读 |
|
当标题、作者/朝代、正文颜色相同但透明度无法表达层级时，必须继续依靠字号和字重区分。

面板默认：

```text
panelEnabled = true
panelColor = rgba(0, 0, 0, 0.42)
```

面板应采用圆角矩形或底部渐变遮罩，不能遮挡图片主体过多。默认面板内边距为正文基准字号的 0.8 倍。

### 4.5 字体家族

默认字体候选顺序：

1. `Microsoft YaHei UI`
2. `Microsoft YaHei`
3. `Noto Sans CJK SC`
4. `SimSun`
5. 系统通用字体

建议默认选择 `Microsoft YaHei UI`，因为其中文显示和屏幕阅读表现较稳定。

高级设置允许：

- 全局字体家族；
- 标题独立字体家族；
- 正文独立字体家族；
- 落款独立字体家族。

第一版界面默认只展示“整体字体”，独立字体放在高级设置中，避免普通用户面对过多选择。

## 5. 间距、行距和对齐规范

### 5.1 块间距

以正文基准字号 `B` 为比例基准：

| 位置 | 默认间距 | 说明 |
|---|---:|---|
| 标题与落款 | `0.35B` | 标题和落款保持关联 |
| 落款与正文 | `0.90B` | 形成明显视觉分组 |
| 标题与正文（无落款） | `0.90B` | 直接使用正文间距 |
| 面板内边距 | `0.80B` | 四周最小内边距 |
| 正文段落之间 | `0.55B` | 仅对显式空行或段落生效 |

所有间距都必须随输出尺寸缩放，并设置最小值：

```text
最小块间距：8 px
最小面板内边距：16 px
```

### 5.2 行距

| 文本块 | 默认行高倍率 | 说明 |
|---|---:|---|
| 标题 | 1.20 | 标题最多两行时保持紧凑 |
| 作者/朝代 | 1.15 | 通常单行 |
| 正文 | 1.60 | 适合中文诗句逐行阅读 |

正文推荐使用固定行高或 `QTextLine::setLeadingIncluded` 等可控方式实现，不能完全依赖不同字体默认行距，以避免不同 Windows 机器出现明显跳动。

### 5.3 对齐

提供三种对齐方式：

- 左对齐；
- 居中对齐；
- 右对齐。

默认规则：

| 锚点 | 默认对齐 |
|---|---|
| 左上、左下 | 左对齐 |
| 居中 | 居中对齐 |
| 右上、右下 | 右对齐 |

用户手动选择对齐方式后，以用户选择为准，不因锚点变化而悄悄覆盖。

标题、落款和正文默认使用同一对齐方式，以保持整体秩序。第一版不支持标题和正文分别对齐，避免设置复杂度过高。

### 5.4 安全区域

默认文字块不应占据整个画布：

- 左右安全边距：画布短边的 5%；
- 上下安全边距：画布短边的 5%；
- 非居中布局最大文字宽度：画布宽度的 46%；
- 居中布局最大文字宽度：画布宽度的 78%；
- 文字块最大高度：画布高度的 46%；
- 居中布局最大高度：画布高度的 70%。

上述限制用于避免正文覆盖图片主体或桌面图标区域。用户可在高级设置中调整最大宽度和最大高度比例，但不得低于安全最小值。

## 6. 字段显示和空字段策略

### 6.1 标题

- `title.trimmed()` 为空时，不显示标题块；
- 不保留标题占位空行；
- 标题只有空格、制表符或换行时，按空字段处理；
- 标题过长时允许最多两行；
- 标题超过最大宽度后优先在标点、空格或自然边界换行；
- 中文标题没有自然断点时允许按字符换行；
- 标题不允许被正文覆盖。

### 6.2 作者和朝代

作者、朝代合并为落款块，但分别绘制，以便控制视觉权重。

显示组合规则：

| 作者 | 朝代 | 显示结果 |
|---|---|---|
| 有 | 有 | `作者 · 朝代` |
| 有 | 无 | `作者` |
| 无 | 有 | `朝代` |
| 无 | 无 | 不显示落款块 |

规则：

- 分隔符默认使用全角中点或视觉等价的 `·`，两侧保留一个窄间距；
- 只显示一个字段时，不显示分隔符；
- 作者和朝代均为空时，标题与正文之间直接使用正文间距；
- 作者或朝代过长时，优先缩小落款字号，不能挤压正文；
- 默认落款最多一行，无法容纳时允许换成两行，但不能出现半个汉字或半个分隔符被裁剪。

### 6.3 正文

- `content.trimmed()` 为空时，禁止生成壁纸并显示“诗词正文不能为空”；
- 保留用户输入的显式换行；
- 统一 `CRLF`、`CR` 为 `LF`；
- 连续空行最多保留一个空行，避免导入数据造成巨大空洞；
- 正文换行优先遵循用户显式换行；
- 单行过长时按中文字符、标点和可断点自动换行；
- 不得因为英文单词、数字或 URL 导致整段超出安全区域。

### 6.4 标签和其他字段

`tags` 不在默认壁纸中显示。第一版不因标签为空或存在而改变正文布局。

## 7. 长文本和溢出策略

### 7.1 默认策略：缩小后失败，不静默裁剪

当前产品已经要求超长诗词不能被静默裁剪。本规范延续这一原则，并细化为：

1. 标题、落款、正文分别测量；
2. 优先保持标题和落款的视觉层级；
3. 正文在允许范围内从默认字号逐步缩小；
4. 正文最小字号为基准正文的 0.70 倍，且不得低于 20 px；
5. 标题最小字号为基准标题的 0.75 倍，且不得低于 28 px；
6. 落款最小字号为默认落款的 0.80 倍，且不得低于 16 px；
7. 缩小到最小值后仍无法放入安全区域时，默认返回“诗词内容过长”，不生成或应用壁纸；
8. 失败时保留上一张有效预览和桌面壁纸；
9. UI 必须提示用户可以缩小字号、增大文字区域、切换到居中布局或编辑正文。

### 7.2 可选策略：省略号

高级设置可以提供“超长正文显示省略号”选项，但默认关闭。

启用后：

- 只能在完整测量失败时触发；
- 只允许省略正文末尾，不允许省略标题或作者；
- 末尾使用单个省略号 `…`；
- 最后一行必须仍然完整落在安全区域内；
- UI 状态必须显示“正文已省略”；
- 历史记录中记录该次使用了省略策略。

### 7.3 最大行数

默认值：

```text
正文最大行数：8 行
标题最大行数：2 行
落款最大行数：2 行
```

最大行数不是用来静默截断，而是用来参与布局测量和溢出判定。超过最大行数后，必须按 7.1 或 7.2 处理。

### 7.4 特殊文本

以下内容按普通 Unicode 文本处理，不得崩溃：

- 中英文混排；
- 生僻字；
- 中文标点；
- 数字；
- Emoji；
- Tab；
- 连续空格；
- `\n` 和 `\r\n` 混合换行。

无法由当前字体显示的字符应使用 Qt 字体回退；若仍无法显示，应在日志和状态中记录，不得把整个诗词块绘制为空白。

## 8. 图片和文字对比度规范

排版好看不能以牺牲可读性为代价。

### 8.1 默认增强

默认开启以下至少一项：

- 半透明黑色底板；
- 文字阴影；
- 文字描边；
- 图片底部渐变遮罩。

当前版本已有 `panelEnabled`、`panelColor`、`shadowEnabled`，应继续保留，并让其作用于全部文本块。

### 8.2 分块对比度

- 标题和正文必须保持可辨识；
- 落款可以弱化，但不能低到无法阅读；
- 颜色透明度的改变不能替代最小字号和字重约束；
- 在默认测试图片集上，标题、正文和落款都必须肉眼可读；
- 文字块底板不能因为标题变大而覆盖图片大面积主体。

### 8.3 颜色设置的产品策略

首版设置界面提供：

- 正文颜色；
- 标题颜色跟随正文或独立设置；
- 落款颜色跟随正文或独立设置；
- 底板颜色和透明度；
- 阴影开关。

默认不在首屏暴露描边宽度、阴影偏移等技术参数，避免设置页继续变得杂乱。

## 9. 设置界面改动要求

关联 `docs/UI_REDESIGN.md` 的“显示设置”标签页，建议改为以下层级。

### 9.1 首屏：排版预设

新增“排版预设”下拉框，提供：

1. **雅致左下（默认）**
   - 左下锚点；
   - 左对齐；
   - 标题半粗；
   - 正文常规；
   - 黑色半透明底板。
2. **留白居中**
   - 居中锚点；
   - 居中对齐；
   - 面板透明度降低；
   - 正文区域加宽。
3. **简洁右下**
   - 右下锚点；
   - 右对齐；
   - 面板更紧凑；
   - 落款弱化。
4. **自定义**
   - 用户修改任意排版参数后自动切换为自定义。

预设切换必须立即刷新预览，但不自动设置桌面。

### 9.2 首屏：基础排版选项

建议直接展示：

- 整体中文字体；
- 正文字号；
- 文字位置；
- 文字对齐；
- 图片适配方式；
- 面板开关；
- 阴影开关。

同时在预览中显示当前诗词的标题、落款和正文，用户无需点击其他页面即可看出层级变化。

### 9.3 “文字层级”折叠面板

新增可折叠区域“文字层级”，包含：

| 选项 | 默认值 | 优先级 |
|---|---|---|
| 标题字号比例 | 150% 正文 | P0 |
| 标题字重 | 半粗 | P0 |
| 标题颜色 | 白色 100% | P1 |
| 作者字号比例 | 72% 正文 | P0 |
| 朝代字号比例 | 68% 正文 | P0 |
| 作者/朝代字重 | 中等/常规 | P1 |
| 作者/朝代颜色 | 白色 72%～92% | P1 |
| 正文行距 | 160% | P0 |
| 标题与落款间距 | 35% 正文字号 | P1 |
| 落款与正文间距 | 90% 正文字号 | P1 |

P0 选项属于第一版必须实现的排版控制；P1 选项可以在高级版本中逐步开放，但产品数据结构应预留。

### 9.4 “长文本”折叠面板

包含：

- 正文最大行数，默认 8；
- 标题最大行数，默认 2；
- 自动缩小字体，默认开启；
- 最小正文比例，默认 70%；
- 超长处理：失败提示 / 末尾省略号，默认失败提示；
- 是否保留显式空行，默认保留一个。

### 9.5 “高级字体”折叠面板

包含：

- 标题独立字体；
- 正文独立字体；
- 落款独立字体；
- 标题、正文、落款独立颜色；
- 字符间距；
- 精确最大宽度比例。

默认折叠，不应占据主界面主要空间。

### 9.6 交互要求

所有排版设置修改后：

- 220ms 防抖刷新预览；
- 预览刷新不调用 Windows 壁纸设置；
- 预览失败保留上一张有效预览；
- 状态栏显示“预览已更新”或具体错误；
- 用户点击“应用当前预览”后才修改真实桌面；
- 修改设置后可选择“保存为默认”，否则只影响当前运行配置的行为应遵循现有产品规范。

### 9.7 设置页布局原则

为了回应“布局杂乱”问题：

- 首屏最多展示 8 个常用控制；
- 高级选项全部折叠；
- 不同时展示 3 个以上颜色按钮；
- 标题、作者、朝代、正文必须以分组卡片或树状层级呈现；
- 每个选项后显示简短结果说明，例如“标题约为正文的 1.5 倍”；
- 预览区始终可见或能一键返回，不要求用户在多个标签页之间来回切换。

## 10. 数据模型和渲染实现建议

### 10.1 `Poem` 模型

当前 `Poem` 已包含：

```text
id
title
author
dynasty
content
tags
enabled
```

第一版不需要为排版增加字段。排版属于显示配置，不应写入每首诗词数据，避免同一首诗词在不同模板下无法复用。

仍需在导入/渲染前统一处理：

- `title`、`author`、`dynasty` 使用 `trimmed()` 判断是否为空；
- `content` 统一换行符；
- 连续空行按规范收敛；
- 不修改用户原始诗词库文件。

### 10.2 `RenderSettings` 演进建议

当前 `RenderSettings` 只有一个 `fontPointSize` 和一个 `textColor`，无法表达本规范要求。建议后续程序实现时增加嵌套排版配置，示例结构如下：

```text
TypographySettings
  baseFontFamily
  titleFontFamilyOverride
  bylineFontFamilyOverride
  bodyFontFamilyOverride
  bodyPointSize
  titleScale
  authorScale
  dynastyScale
  titleWeight
  bylineWeight
  bodyWeight
  titleColor
  authorColor
  dynastyColor
  bodyColor
  alignment
  titleLineSpacing
  bodyLineSpacing
  titleBylineSpacing
  bylineBodySpacing
  maxTextWidthRatio
  maxTextHeightRatio
  titleMaxLines
  bylineMaxLines
  bodyMaxLines
  autoShrinkEnabled
  minBodyScale
  overflowPolicy
```

也可以暂时将字段平铺到 `RenderSettings`，但不建议继续只增加零散字段。排版配置应作为一个逻辑整体进行保存、加载、迁移和测试。

旧配置兼容策略：

- 旧 `fontFamily` 映射为 `baseFontFamily`；
- 旧 `fontPointSize` 映射为 `bodyPointSize`；
- 旧 `textColor` 映射为 `bodyColor`；
- 旧 `panelEnabled`、`panelColor`、`shadowEnabled` 保持有效；
- 标题、作者、朝代使用本规范默认比例；
- 第一次加载旧配置后不应改变用户原始诗词数据。

### 10.3 渲染器实现边界

`WallpaperRenderer::render()` 后续应按以下阶段执行：

```text
1. 校验 source、targetSize、poem.content
2. 准备背景图
3. 规范化 title/author/dynasty/content
4. 构造 TitleBlock、BylineBlock、BodyBlock
5. 为三个文本块分别创建 QFont
6. 分别测量宽度、高度、行数
7. 执行自动缩小和溢出判定
8. 计算块间距和总文本区域
9. 根据 Anchor 和 Alignment 定位整体区域
10. 绘制底板/渐变
11. 按标题、落款、正文顺序分别绘制
12. 返回完整输出图或明确错误
```

不得继续使用一个 `QString text = lines.join("\\n")` 再一次性绘制的方式作为最终实现。

### 10.4 可测试性

渲染器应能够在测试中单独获得：

- 最终使用的标题字号、正文字号、落款字号；
- 每个文本块的矩形区域；
- 实际换行行数；
- 是否触发自动缩小；
- 是否触发省略号；
- 字体回退结果；
- 溢出错误原因。

如果不希望公开内部结构，至少应提供可序列化的布局诊断信息，供测试和日志使用。

## 11. 具体验收标准

验收环境至少包括：

- Windows 10 或 Windows 11 64 位；
- Qt 发布包，不依赖开发环境；
- 1920×1080、100% DPI；
- 2560×1440、150% DPI；
- 一张明亮背景、一张暗色背景、一张高细节背景；
- 中文字体可用和指定字体不可用两种情况。

## 12. 产品验收门槛

本排版改造只有同时满足以下条件，产品才可判定通过：

### P0 必须全部通过

- TY-001～TY-006；
- TY-010～TY-014、TY-016；
- TY-020～TY-025；
- TY-030～TY-033、TY-036；
- TY-040～TY-043、TY-045～TY-047；
- TY-050～TY-052、TY-054；
- TY-060～TY-065。

### P1 建议通过

- TY-015、TY-026、TY-034、TY-035、TY-044、TY-048、TY-053。

### 视觉验收底线

在默认排版模板下，产品、程序员和测试三方共同查看至少 6 张输出壁纸：

1. 标题、作者、朝代、正文全部存在；
2. 标题为空；
3. 作者为空；
4. 朝代为空；
5. 长正文；
6. 亮色复杂背景。

如果出现以下任一情况，则产品验收不通过：

- 四类文字看起来仍像同一字号的流水账；
- 标题不比正文突出；
- 作者/朝代抢过正文视觉焦点；
- 正文行距过密，无法连续阅读；
- 字段为空时出现明显空白行；
- 长文本被无提示截断；
- 预览和最终桌面效果不一致；
- 修改排版设置后仍需重启程序才能看到效果。

## 13. 给程序员 agent 的实现任务边界

本规范不是代码实现方案，但建议按以下顺序落地：

1. 增加排版配置对象，并完成旧配置迁移；
2. 将 `WallpaperRenderer` 的单一文本绘制改为三块独立布局；
3. 实现标题、落款、正文分别测量和绘制；
4. 实现空字段收缩和显式换行规范化；
5. 实现自动缩小、最大行数和溢出错误；
6. 增加预设和高级设置 UI；
7. 保证设置改变只刷新预览，不自动设置桌面；
8. 增加布局诊断信息和单元测试；
9. 完成亮色、暗色、长文本、缺字段和字体回退回归测试；
10. 最后由产品进行视觉验收。

本轮产品明确：**不要求现在修改 `src/core/renderer.cpp` 或 `src/core/models.*`，只要求程序员依据本规范进入下一轮实现。**
