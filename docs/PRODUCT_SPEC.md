# Windows 诗词壁纸软件 MVP 产品规格

- **文档状态**：第一轮产品设计，供产品、程序员、测试三方评审
- **目标版本**：MVP 0.1
- **适用工程**：当前仓库的 C++17 + Qt 6.8.3 + Qt Widgets 工程
- **目标平台**：Windows 10/11，64 位优先
- **核心原则**：离线优先、本地资源、轻量、可恢复、可测试

## 1. 产品概述

### 1.1 产品定位

一款常驻 Windows 桌面的轻量诗词壁纸工具。用户准备本地图片和诗词库后，软件可以随机组合一条诗词与一张图片，生成带诗词的壁纸并设置为 Windows 桌面背景；用户也可以手动立即切换，或按固定时间间隔自动切换。

### 1.2 MVP 成功标准

用户首次启动后，在不联网、不注册、不依赖服务器的情况下，能够完成以下闭环：

1. 导入或选择本地图片目录；
2. 导入或编辑诗词库；
3. 选择诗词和图片的随机规则及切换间隔；
4. 点击“立即切换”；
5. 软件生成合成壁纸并成功设置为 Windows 桌面背景；
6. 到达设定时间后自动完成下一次切换；
7. 关闭并重新打开软件后，配置仍然存在，软件可以继续工作。

### 1.3 MVP 关键约束

- 不提供联网诗词、在线图片、账号、云同步和远程推送。
- 所有输入资源均来自用户本机，路径可能包含中文、空格和非 ASCII 字符。
- 诗词渲染必须支持中文字体、换行和基本的可读性保护。
- 壁纸设置失败时，不得覆盖或破坏用户当前壁纸。
- 生成的合成图片使用应用专属缓存目录，不能污染用户图片库。
- UI 与核心业务逻辑分离，随机抽取、渲染和 Windows 壁纸设置应支持无界面测试。

## 2. 用户角色与使用场景

### 2.1 目标用户

- 希望桌面具有中国古典诗词氛围的普通 Windows 用户。
- 有自定义图片和诗词偏好的用户。
- 希望通过定时切换保持桌面变化，但不想使用联网壁纸服务的用户。

### 2.2 典型场景

1. **首次配置**：用户打开软件，选择图片目录，导入内置示例或自己的诗词 JSON，立即生成一张壁纸。
2. **日常切换**：用户通过托盘菜单点击“下一张”，快速更换壁纸，不必打开主窗口。
3. **定时切换**：用户设置每 30 分钟切换，软件在后台运行并自动生成壁纸。
4. **内容维护**：用户增加、删除、启用或停用诗词条目和图片目录。
5. **故障恢复**：某张图片损坏或诗词库为空时，软件提示具体原因并继续保持当前桌面，不崩溃。

## 3. 用户流程

### 3.1 首次启动流程

1. 启动应用。
2. 主窗口显示当前状态：图片资源数量、启用诗词数量、定时状态、最近一次切换结果。
3. 若没有可用图片或诗词，显示引导提示和“添加图片目录”“导入诗词库”操作。
4. 用户添加图片目录和诗词库。
5. 软件扫描资源并显示有效数量、跳过数量及失败原因摘要。
6. 用户可在“显示设置”中选择诗词位置、字体、字号、颜色、阴影和图片适配方式；MVP 提供默认值。
7. 用户点击“立即切换”。
8. 软件随机选择一条启用诗词和一张可用图片，生成合成图片。
9. 软件调用 Windows 桌面背景 API 设置壁纸。
10. 主窗口更新预览、最近使用内容和成功时间；托盘图标进入可用状态。

### 3.2 手动切换流程

1. 用户点击主窗口“立即切换”，或点击托盘菜单“下一张”。
2. 软件按当前配置抽取诗词和图片。
3. 软件生成临时合成壁纸并校验文件可读。
4. 软件设置 Windows 桌面背景。
5. 成功：更新状态、预览和历史记录。
6. 失败：显示可理解的错误信息，保留当前桌面和上一次成功结果。

### 3.3 定时切换流程

1. 用户开启定时切换。
2. 用户选择间隔：5、10、15、30、60、120 分钟，或输入 1–1440 分钟的整数值。
3. 软件立即保存配置，并显示“下次切换时间”。
4. 定时器到期后执行与手动切换相同的生成、设置和记录流程。
5. 切换失败时记录错误并按下一次周期继续重试，不因单次失败停止定时任务。
6. 用户关闭定时开关、退出应用或从托盘退出后，定时任务停止。

### 3.4 资源维护流程

#### 图片库

1. 用户点击“添加图片目录”。
2. 选择本机目录，可添加多个目录。
3. 软件递归扫描目录（MVP 默认递归，可在实现评审时确认）。
4. 识别支持的图片格式，去重并统计有效文件。
5. 用户可移除目录；移除目录不删除磁盘上的原文件。
6. 图片库为空时，禁止执行切换并提示补充资源。

#### 诗词库

1. 用户点击“导入诗词库”，选择 UTF-8 JSON 文件。
2. 软件校验 JSON 结构，逐条校验必填字段。
3. 导入成功后显示有效条数和无效条数。
4. 用户可以在列表中查看、启用/停用、删除条目。
5. MVP 可提供“新增诗词”表单和“导出诗词库”功能；若开发资源有限，至少保证 JSON 导入可用。
6. 删除或停用仅影响软件库，不修改用户原始导入文件。

### 3.5 退出与恢复流程

- 点击窗口关闭按钮：默认隐藏到系统托盘，不退出进程。
- 托盘菜单提供“打开主窗口”和“退出”。
- 退出时保存配置、停止定时器并正常释放临时资源。
- 再次启动时读取上次配置；若路径或文件已不存在，标记为不可用并提示，不崩溃。
- MVP 不要求开机自启；但程序退出后不应继续修改桌面。

## 5. MVP 范围与产品决策

### 5.1 桌面与多显示器策略

MVP 默认以 Windows 当前桌面工作区的主屏分辨率生成一张壁纸，并设置为系统桌面背景；所有显示器使用同一张壁纸。这样可以减少 Windows 多显示器兼容差异和测试成本。程序员需确认 Windows API 的实际行为，并在 UI 中明确“当前版本所有屏幕使用同一张图”。

如果主屏工作区尺寸获取失败，回退到主屏分辨率；仍失败则回退到源图片尺寸并给出警告。

### 5.2 图片适配策略

MVP 提供三种模式：

- **铺满（Fill）**：保持比例缩放后裁剪，覆盖整个画布，不留黑边。
- **适应（Fit）**：保持比例缩放完整显示，空白区域使用可配置的深色背景填充。
- **拉伸（Stretch）**：直接拉伸到画布尺寸，可能变形。

默认使用“铺满”。图片方向、EXIF 旋转和极端尺寸由 Qt 图片加载能力处理；无法解码的资源跳过。

### 5.3 诗词排版策略

MVP 使用一套默认模板，至少渲染：

- 标题（可选）
- 作者（可选）
- 正文

默认将文字放置在画布下方或右下方的安全区域，自动换行，限制最大文字区域，不覆盖边缘 5% 区域。具体 UI 可使用“左上、左下、居中、右上、右下”五个锚点；MVP 不要求逐字排版或复杂书法效果。

默认文字样式：白色文字、半透明深色底板或阴影、自动换行。用户可修改字体族、字号、颜色、透明度、阴影开关和位置。若用户选择的字体不可用，回退到系统中文字体并提示。

### 5.4 随机策略

- 诗词和图片分别独立随机，允许重复。
- 软件运行期间应尽量避免连续两次抽到相同的诗词或图片；当库中只有一个有效项时允许重复。
- 随机种子由应用启动时初始化；核心随机服务应允许测试注入固定种子或固定序列。
- 本 MVP 不做“完全不重复直到全部用完”的洗牌队列，避免状态复杂化。

### 5.5 切换并发策略

同一时刻只允许一个切换任务运行。手动切换与定时切换同时触发时，后到请求应被忽略或排队一次，不能并发写同一个输出文件、不能导致多个壁纸设置请求交叉覆盖。

## 6. 配置与数据格式建议

### 6.1 存储位置

建议使用 Qt 的 `QStandardPaths`：

- 配置：`QStandardPaths::AppConfigLocation` 下的 `config.json`
- 应用数据：`QStandardPaths::AppDataLocation`
- 缓存：应用数据目录下的 `cache/wallpapers/`
- 日志：应用数据目录下的 `logs/`

实际路径由程序运行环境决定，UI 应提供“打开数据目录”或在“关于/诊断”中显示路径。所有路径使用绝对路径保存，读取后先检查存在性。

### 6.2 主配置 `config.json`

建议结构如下，字段名可在开发前冻结：

```json
{
  "schemaVersion": 1,
  "imageSources": [
    {
      "path": "C:/Users/example/Pictures/poetry",
      "enabled": true,
      "recursive": true
    }
  ],
  "poetryLibrary": {
    "path": "C:/Users/example/Documents/poetry.json",
    "embeddedEntries": [],
    "disabledIds": []
  },
  "schedule": {
    "enabled": true,
    "intervalMinutes": 30
  },
  "render": {
    "placement": "bottomRight",
    "fontFamily": "Microsoft YaHei UI",
    "fontPointSize": 28,
    "textColor": "#FFFFFFFF",
    "panelEnabled": true,
    "panelColor": "#99000000",
    "shadowEnabled": true,
    "fitMode": "fill",
    "canvasBackgroundColor": "#FF202020"
  },
  "runtime": {
    "lastSuccessfulWallpaper": "C:/.../cache/wallpapers/wallpaper-20260804-172200.jpg",
    "lastPoetryId": "poem-001",
    "lastImagePath": "C:/.../image.jpg"
  }
}
```

要求：

- 配置文件写入采用临时文件 + 原子替换，避免程序异常退出造成半文件。
- 缺少字段使用默认值；未知字段忽略，便于未来向前兼容。
- `schemaVersion` 增加时提供迁移策略，不直接清空用户配置。
- 路径中的反斜杠按 JSON 规则转义；推荐内部统一使用 Qt `QDir`/`QFileInfo` 处理。

### 6.3 诗词库 JSON

推荐 UTF-8 编码，顶层对象包含版本和数组：

```json
{
  "schemaVersion": 1,
  "poems": [
    {
      "id": "poem-001",
      "title": "静夜思",
      "author": "李白",
      "dynasty": "唐",
      "content": "床前明月光\n疑是地上霜\n举头望明月\n低头思故乡",
      "tags": ["唐诗", "思乡"],
      "enabled": true
    }
  ]
}
```

字段规则：

- `id`：字符串；导入时为空则生成稳定的本地 ID，重复 ID 需提示并按产品确定的策略处理，建议保留第一条、跳过后续重复条目。
- `title`、`author`、`dynasty`：可为空；`title` 和 `author`为空时仍允许导入，但正文必须有效。
- `content`：必填，去除首尾空白后不可为空；保留换行。
- `tags`：可选字符串数组。
- `enabled`：可选，默认 `true`。

建议导入采用“合并”模式：以 `id` 去重，把新条目加入内置/本地库；另提供“覆盖当前库”选项属于 P1。MVP 至少实现一种明确且可测试的导入策略，不能静默丢失已有条目。

### 6.4 图片资源模型

图片不复制进应用数据目录，保存目录路径并在每次扫描时生成当前文件清单。清单中的单个资源至少包含：绝对路径、文件大小、最后修改时间、是否可解码。可以使用路径 + 文件大小 + 修改时间作为缓存键的一部分。

### 6.5 合成壁纸命名

建议格式：`wallpaper-yyyyMMdd-HHmmss-zzz-<short-id>.jpg`。输出写入临时文件，写入成功并可重新打开后，再调用 Windows API 设置；设置成功后再更新运行时状态。保留最近 10 张成功壁纸，其他缓存按容量或数量清理。清理缓存不得删除当前正在使用的壁纸文件。

## 7. 界面信息架构

### 7.1 主窗口

建议使用单窗口 + 分组区域：

1. **状态卡片**：当前壁纸、定时状态、下次切换时间、最后结果。
2. **快速操作**：立即切换、暂停/恢复定时、打开缓存目录。
3. **图片库**：目录列表、添加、移除、重新扫描、有效图片数量。
4. **诗词库**：导入、导出（如实现）、条目数、列表、启用/停用、删除。
5. **显示设置**：适配方式、位置、字体、字号、颜色、底板/阴影。
6. **日志/诊断入口**：最近错误摘要和打开日志目录。

### 7.2 状态与反馈

所有异步或耗时操作至少有三种状态：进行中、成功、失败。扫描和生成期间禁用会导致冲突的重复操作，窗口仍可响应关闭和取消（若实现取消）。错误提示应包含：操作、原因、用户可采取的动作。

示例：

- “未找到可用图片，请添加包含 PNG/JPG 图片的目录。”
- “诗词库导入完成：有效 20 条，跳过 2 条。详情已写入日志。”
- “壁纸设置失败：Windows API 返回错误。当前桌面未改变。”

## 8. 详细可验收标准

以下标准作为产品验收基线。除特别说明外，验收环境为 Windows 10/11 64 位、普通用户权限、中文系统，使用本地测试资源。

### 8.1 启动、窗口和托盘

- **AC-001**：程序启动后 3 秒内显示主窗口，窗口不出现 Hello World 占位内容，不崩溃。
- **AC-002**：关闭主窗口后进程仍在运行且托盘图标存在；托盘“打开”可恢复窗口。
- **AC-003**：托盘“退出”后进程结束，定时器停止，不再触发壁纸切换。
- **AC-004**：重复启动不会导致两个实例同时执行定时切换。MVP 至少应有清晰行为：允许多实例但每个实例不互相损坏，或限制单实例并提示；推荐单实例。
- **AC-005**：窗口在无图片、无诗词、配置损坏、资源路径失效时仍可打开，并明确显示待处理问题。

### 8.2 图片库

- **AC-010**：添加存在的图片目录后，界面显示目录路径和扫描结果。
- **AC-011**：扫描至少识别 PNG、JPG/JPEG、BMP；WEBP 是否支持必须依据运行环境验证并在 UI/文档中保持一致。
- **AC-012**：混合目录中包含损坏图片、文本文件和不支持格式时，程序不崩溃，仅将可用图片加入候选库，并报告跳过数量。
- **AC-013**：同一文件通过多个目录来源被发现时，候选库不重复抽取同一绝对路径。
- **AC-014**：移除目录只从候选库移除资源，不删除目录或目录内文件。
- **AC-015**：目录不存在或无权限时显示不可用状态；切换时不能因该目录异常而终止整个应用。
- **AC-016**：重新扫描能发现新增文件、移除已删除文件，并反映最新有效数量。

### 8.3 诗词库

- **AC-020**：导入合法 UTF-8 JSON 后，条目数量、标题、作者和正文可在列表中查看。
- **AC-021**：正文为空、JSON 语法错误、顶层结构错误、字段类型错误的条目不会进入可抽取库；程序不崩溃，并显示有效/跳过数量。
- **AC-022**：中文、换行、标点、表情或其他 Unicode 字符不会因导入而乱码；无法渲染的字符应使用系统字体回退或给出提示。
- **AC-023**：停用条目不会被随机抽取；重新启用后可被抽取。
- **AC-024**：删除条目后，重启软件该条目不会恢复，除非用户再次从源文件导入。
- **AC-025**：已有库导入新库时，合并/覆盖规则与界面提示一致，不得静默清空已有数据。
- **AC-026**：诗词库文件被外部修改或删除后，软件下次读取/刷新能识别并提示；已保存的内嵌条目不应导致崩溃。

### 8.4 随机抽取和切换

- **AC-030**：存在至少 1 条有效诗词和 1 张有效图片时，“立即切换”可完成抽取、合成和壁纸设置。
- **AC-031**：诗词库为空或图片库为空时，点击切换不会生成空白壁纸，不会调用设置壁纸操作，并提示缺少哪类资源。
- **AC-032**：在候选库有多个项目时，多次切换的抽取结果可变化；测试模式可通过固定随机源复现指定结果。
- **AC-033**：候选库只有一个项目时，允许重复使用，不应报“随机失败”。
- **AC-034**：连续两次切换默认不重复相同诗词或相同图片；只有单项候选时可重复。
- **AC-035**：切换过程中再次点击按钮不会并发生成多个输出或损坏配置；用户得到“正在切换”状态或一次可预期的排队结果。
- **AC-036**：生成的合成图可以被 Qt 重新打开，尺寸等于目标画布尺寸，内容同时包含图片和诗词文字。
- **AC-037**：设置壁纸成功后，Windows 桌面背景更新为本次生成文件；主窗口预览与生成文件一致。
- **AC-038**：设置壁纸失败、输出文件无法写入或生成失败时，当前桌面保持不变，界面展示失败原因并写入日志。
- **AC-039**：用户原始图片文件不会被覆盖、重编码或移动。
- **AC-040**：成功切换后运行时状态、最近一次诗词 ID、图片路径和生成文件路径持久化；重启后可显示。

### 8.5 合成与显示设置

- **AC-050**：Fill、Fit、Stretch 三种适配方式分别表现符合定义；源图宽高比与屏幕不一致时也不崩溃。
- **AC-051**：文字长于画布可用区域时自动换行或缩小到可读范围，不得被完全裁剪；极端超长正文有明确限制或提示。
- **AC-052**：标题、作者、正文的换行和空字段处理符合约定，不出现多余空行或“undefined/null”文本。
- **AC-053**：文字位置不会固定贴到画布边缘；默认留出安全边距。
- **AC-054**：文字颜色、字号、字体、底板和阴影设置能影响下一次生成；设置重启后保留。
- **AC-055**：字体不存在时使用明确的回退字体，生成仍可完成，并在日志中记录回退。
- **AC-056**：至少验证 1920×1080 和 2560×1440 目标尺寸；UI 缩放 125%/150% 时设置值和生成尺寸不发生异常偏差。
- **AC-057**：同一目标图片和同一文字设置下，重复生成结果稳定，除随机资源外不受窗口尺寸影响。

### 8.6 定时切换

- **AC-060**：开启定时后显示当前间隔和下次切换时间。
- **AC-061**：到达间隔后触发一次完整切换；切换成功后按同一间隔计算下一次时间。
- **AC-062**：关闭定时或点击暂停后，不再触发新的定时切换；恢复后重新计算下一次时间。
- **AC-063**：程序重启后，定时开关和间隔按配置恢复；是否立即补偿错过的切换必须固定为一种行为，推荐“不补偿，按启动时间重新计时”。
- **AC-064**：定时切换失败不会退出程序，也不会自动关闭定时；日志记录失败，下一周期仍会执行。
- **AC-065**：手动切换正在执行时定时到期，不能产生并发切换或交叉写文件。

### 8.7 配置、缓存和日志

- **AC-070**：配置文件不存在时自动创建默认配置；首次启动不因缺少配置报错。
- **AC-071**：配置 JSON 被截断或格式错误时，程序备份损坏文件或至少保留原文件，使用默认配置启动并提示用户。
- **AC-072**：配置写入使用安全替换策略；程序异常中断后再次启动不会读取半截 JSON 作为有效配置。
- **AC-073**：缓存输出不写入用户图片目录；清理缓存不删除源图片。
- **AC-074**：缓存清理不会删除当前壁纸对应文件，清理后最近一次壁纸仍可读取。
- **AC-075**：日志包含时间、级别、操作阶段和错误信息；敏感信息不写入日志。日志文件应有大小或文件数量上限。
- **AC-076**：配置路径、缓存路径和日志路径在不同 Windows 用户目录下均能正常工作，路径包含中文和空格时可用。

### 8.8 性能与稳定性

- **AC-080**：在 200 张普通本地图片、1000 条诗词的测试数据下，首次扫描最终完成且界面保持可响应；扫描期间有进行中提示。
- **AC-081**：单次切换不应因加载整库图片像素数据而长期占用内存；程序员需给出可接受的峰值内存基线，产品建议常规资源下不超过 200 MB。
- **AC-082**：连续手动切换 100 次不崩溃、不持续增长到不可接受的内存占用，缓存按策略受控。
- **AC-083**：资源路径、JSON、输出文件、Windows API 失败均可恢复，禁止使用未捕获异常导致进程退出。
- **AC-084**：退出时不存在后台线程继续访问已销毁的 Qt 对象；重复启动/退出 20 次不出现明显残留进程。

## 9. 程序员 agent 需要关注并提出的问题

以下问题在进入实现前需要程序员给出技术结论；如果结论影响用户行为，应回写本规格并由产品确认。

1. **Windows 壁纸 API**：采用 `SystemParametersInfoW(SPI_SETDESKWALLPAPER, ...)` 是否满足 Windows 10/11 目标；需要哪些 `QFile` 路径到 UTF-16 的转换和错误码处理？是否需要设置 `SPIF_UPDATEINIFILE | SPIF_SENDCHANGE`？
2. **多显示器行为**：系统 API 在当前 Windows 版本下对多显示器的实际效果是什么；主屏统一壁纸是否可稳定实现？
3. **目标画布尺寸**：用 `QScreen` 的 available geometry、geometry 还是 Windows 虚拟桌面尺寸？高 DPI 和缩放比例下应使用物理像素还是逻辑像素？
4. **图片格式能力**：当前 Qt 安装实际包含哪些 imageformats 插件，尤其是 WEBP；MVP 是否将 WEBP 从支持列表中移出以避免部署不一致？
5. **渲染输出格式**：PNG 与 JPG 哪个更适合当前质量、透明度和文件大小要求；输出写入及原子替换如何实现？
6. **线程模型**：目录扫描、图片解码和合成是否放入 worker 线程；如何通过 signal/slot 更新 UI 并安全取消/退出？
7. **随机可测试性**：是否抽象 `IRandomSource` 或等价注入点，使测试可固定选择结果；如何测试“尽量避免连续重复”？
8. **壁纸设置可测试性**：是否抽象 `IWallpaperSetter`，提供真实 Windows 实现和测试 fake；真实 API 失败时如何注入错误？
9. **配置兼容**：使用 `QJsonDocument` 直接读写还是引入其他依赖；原子保存、schema 迁移和损坏恢复怎样落地？
10. **诗词导入策略**：内置条目、外部文件条目和用户编辑条目如何建模；合并时重复 ID、删除和停用状态怎样保持？
11. **并发与节流**：定时器触发时手动切换如何去重；重复点击如何处理；切换操作是否需要任务 ID？
12. **缓存回收**：如何识别当前壁纸文件，如何防止清理任务删除当前壁纸；缓存数量、总大小和异常文件的回收规则是什么？
13. **单实例**：Qt 6.8.3 工程中采用何种无第三方依赖的单实例方案；如果暂不实现，如何避免两个实例同时写状态？
14. **托盘兼容性**：`QSystemTrayIcon` 在 Windows 10/11 的显示和退出行为是否稳定；无托盘可用时的降级方案是什么？
15. **部署**：发布包需要哪些 Qt DLL、平台插件和 imageformats 插件；是否通过 `windeployqt` 验证干净机器启动？
16. **隐私与权限**：是否只需要普通用户权限；日志和配置是否会记录用户完整路径，产品是否接受这种本地诊断信息？

程序员提交实现方案时，至少应提供模块边界建议：`ConfigStore`、`ImageLibrary`、`PoetryLibrary`、`RandomPicker`、`WallpaperRenderer`、`WallpaperSetter`、`Scheduler`、`Tray/MainWindow`，以及各模块的可测试接口。

## 10. 测试 agent 需要关注并提出的问题

1. 是否具备 Windows 10 和 Windows 11 的实际测试环境；是否覆盖中文用户名、中文路径、空格路径和非 ASCII 文件名？
2. 是否有固定的最小测试资源集：正常图片、超宽/超高图片、损坏图片、无权限目录、空目录、超长诗词、空字段和非法 JSON？
3. 测试如何避免直接依赖真实桌面状态；是否使用 fake 壁纸设置器验证调用参数，并仅安排少量 Windows API 集成测试？
4. 真实壁纸集成测试如何保存并恢复测试前桌面，避免污染用户环境；测试失败时如何清理？
5. 如何验证合成图确实包含目标文字，而不是只验证文件存在；是否采用像素区域检查、OCR（可选）或渲染器的结构化测试？
6. 如何在不等待真实 30 分钟的情况下测试定时器；是否支持注入时钟、手动触发 tick 或将分钟转换为测试毫秒？
7. 如何验证随机逻辑可重复；测试应覆盖单项库、多项库、连续不重复和固定随机序列。
8. 如何验证配置损坏恢复、未知字段忽略、缺失字段默认值和 schema 迁移？
9. 如何验证扫描/合成线程在关闭窗口、退出托盘、连续点击时不会访问已释放对象？
10. 如何测试缓存上限和“当前壁纸不可删除”规则；如何制造输出文件写入失败、文件锁定和磁盘空间不足？
11. 如何测试 Windows API 失败、返回错误码、路径包含 Unicode 和长路径等系统边界？
12. 如何验证 DPI 125%/150%、1920×1080、2560×1440 和多显示器环境下的目标尺寸与显示位置？
13. 是否需要静态检查、AddressSanitizer/运行时检查、崩溃日志和连续运行稳定性测试？
14. 测试报告是否按 AC 编号记录环境、前置条件、步骤、实际结果、日志和截图，以便产品验收？

测试 agent 应优先产出：单元测试矩阵、集成测试矩阵、手工验收清单和缺陷严重等级规则。P0 缺陷包括崩溃、误删用户文件、错误覆盖当前壁纸、配置丢失、定时器失控和中文内容不可用。

## 11. 三方协作与迭代门禁

产品、程序员和测试按以下顺序协作：

1. **产品评审**：程序员和测试针对本规格提出疑问，尤其是第 9、10 节；产品补充或明确决策。
2. **规格冻结**：为每个影响实现的问题记录决策，冻结 P0 功能、数据字段和 AC 编号。
3. **开发实现**：程序员按模块实现，不直接把业务逻辑堆在 `main.cpp` 或窗口类中；每个模块提供可测试入口。
4. **测试准备**：测试 agent 基于 AC 编号准备自动化和手工用例，优先 fake 外部依赖。
5. **测试与修复**：发现缺陷后，程序员修复并补充回归测试；涉及需求歧义的缺陷回到产品决策。
6. **产品验收**：产品按本文件验收，重点检查核心闭环和 P0 缺陷；不通过则回到“设计—开发—测试—修复—验收”循环。
7. **MVP 发布条件**：所有 P0 验收项通过；没有阻断级或高优先级未解决缺陷；干净 Windows 环境可以启动；配置、缓存、日志和部署说明齐全。

## 12. 第一轮待确认决策

以下事项不应阻塞文档评审，但必须在开发开始前明确：

- 是否接受 MVP 所有显示器使用同一张壁纸。
- 诗词库导入是默认“合并”还是默认“覆盖”；本规格推荐合并。

- 预览是否必须展示真实桌面当前壁纸；MVP 只要求展示最近一次成功生成的合成图。
